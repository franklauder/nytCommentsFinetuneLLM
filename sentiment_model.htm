Introduction

Sentiment analysis involves assigning predefined categories to text, We use use our understanding of the emotional intent of words to infer whether a section of text is negative, neutral, or positive. For our project we will predict sentiment using a pre-trained large language model (llm) from Hugging Face which we will fine-tune on our specific data. A pre-trained model is a LLM trained on a broad dataset to learn general patterns. Through this process is where model parameters and weights are learned. This can be a time-consuming process thus by using a pre-trained the heavy lifting has been borne by the authors of the model . This makes it easier to update the weights of the model on specific data to adapt it for specialized tasks. For the fine-tuning we will use a New York Times 2017 dataset of comments already including sentiment labels. This was accomplished in a previous project using the AFINN method. The AFINN method is a rule-based approach which has a dictionary of words and each word has an intensity score ranging from -5 to 5. The overall sentiment score of a text is calculated by summing the intensity scores. Fine-tuning of the pre-trained model is different as it is a machine learning process. We train the model on a training subset of our specific data and evaluate it on a testing subset of our specific data. These models differ from rule-based methods as they do not look at words in isolation; they look at the whole sentence, understand word order, context, and sarcasm. Once the fine-tuning of the pre-trained model is finished, we will use it to predict sentiment of unlabeled comments from the New York Times 2018 dataset.

We will be using the pre-trained cardiffnlp/twitter-roberta-base-sentiment-latest model. The license can be viewed at the link below.

Tokenize

Tokenization breaks text into manageable units or tokens. Tokenization helps pre-process text data, simplifying tasks such as filtering out punctuation, converting to lowercase, and handling special characters. It also transforms text into numerical IDs which transformers and LLMs require. Tokenization has different methods such as splitting text into individual words,splitting words into sub-words, and breaking text into individual characters. For our model we will split our data into individual words.

Show Code 
tokenizer = AutoTokenizer.from_pretrained("cardiffnlp/twitter-roberta-base-sentiment-latest")

We will create a function that will will transform the text in the dataset to tokens.

batch[‘text’] - all individual comments are grouped together for simultaneous processing by the tokenizer.

padding=max-length - shoter sequences, each row of comments, will be padded up to the maximum length set by the mdoel.

truncation=True - text sequences, each row of comments, that exceed the maximum length (input length) allowed by the model will be shortened.

Metrics

Show Code 
from sklearn.metrics import accuracy_score, precision_score, recall_score, f1_score
Show Code 
def compute_metrics(pred):
    """
        Calculates evaluation metrics.

        Args:
            pred: predictions from model.

        Returns:
                accuracy,precision, recall, f1 scores.

    """

    labels = pred.label_ids
    preds = pred.predictions.argmax(-1)

    acc = accuracy_score(labels, preds)
    prec = precision_score(labels, preds, average='weighted')
    rec = recall_score(labels, preds, average='weighted')
    f1 = f1_score(labels, preds, average='weighted')

    return {"accuracy": acc, "precision": prec, "recall": rec, "f1": f1}

The function creates the computation of our selected metrics for use during the model evaluation on our validation set.

Metric definition:

• Accuracy-measures the number of predictions that are correct as a percentage of the total number of predictions that are made. As an example, if 90% of your predictions are correct, your accuracy is simply 90%. Calculation: number of correct predictions/Number of total predictions. TP+TN/(TP+TN+FP+FN)

• Precision-tells us about the quality of positive predictions. It may not find all the positives but the ones that the model does classify as positive are likely to be correct. As an example, out of everyone predicted to have defaulted, how many of them did default? So, within everything that has been predicted as positive, precision counts the percentage that is correct. Calculation: True positives/All Positives. TP/(TP+FP)

• Recall- tells us about how well the model identifies true positives. The model may find a lot of positives, yet it also will incorrectly detect many positives that are not actually positives. Out of all the patients who have the disease, how many were correctly identified? So, within everything that is positive, how many did the model successfully find? A model with low recall is unable to find all (or a large part) of the positive cases in the data. Calculated as: True Positives/ (False Negatives + True Positives)

• F1 Score-The F1 score is defined as the harmonic mean of precision and recall. The formula for the F1 score is the following: 2 times(precision*Recall)/ (Precision + Recall)) Since the F1 score is an average of Precision and Recall, it means that the F1 score gives equal weight to Precision and Recall.

Training Arguments:

  • Output_dir: the directory where we will store the results of the model.

  • overwrite_ouput_dir: When set to true, the output directory is overwritten on a new training of the model.

  • eval_strategy: The interval for evaluating the model. For our training we have set it to evaluate after each epoch*.

  • save_strategy: How often to save the model. We have set it to after each epoch.

  • learning_rate: controls how quickly the model’s parameters move towards the optimal solution (minimizing the loss function**)

  • per_device_train_batch: subset of the entire training dataset. It is the number of samples processed before the model is updated. per_device_eval_batch_size: is the number of samples processed before the model is evaluated.

  • weight_decay: used to discourage model from using large weight values during training. Prevents overfitting.

  • logging_dir: directory where the logs are saved.

  • save_steps: Determines how frequently the model’s checkpoint is saved during training.

*An epoch is the number of times that the model will work through the entire training set. This is also known as iteration. In each epoch, the training code updates the weights of the model iteration during which we update the paramters for all our training samples. Updating model weights aims to lower the risk of errors from the model predictions and improve accuracy.

Terms for confusion matrix:

We should note that most confusion matrices have just a positive and negative class. Our model has three classes with neutral being the additional class.

True Positive (TP)

The predicted value matches the actual value.
The actual value was positive, and the model predicted a positive value.

True Negative (TN)

The predicted value matches the actual value
The actual value was negative, and the model predicted a negative value.

True Neutral (TL)

The predicted value matches the actual value
The actual value was neutral, and the model predicted a neutral value.

False Positive (FP)

The predicted value was falsely predicted.
The actual value was negative or neutral, but the model predicted a  positive value.

False Negative (FN)

The predicted value was falsely predicted.
The actual value was neutral or positive, but the model predicted a negative value.

False Neutral (FL)

The predicted value was falsely predicted.
The actual value was negative or positive, but the model predicted a neutral value.

Show Code 
def get_prediction(text):

    """
        Applies fine-tuned model and tokenizer to predict sentiment

        Args: 
            text: A string of text.

        Returns: 
            probabilites: predicted probability of each sentiment. Probabilites sum to 1.
            id2label[pred]: predicted sentiment label.
    """

    input_encoded = new_tokenizer(text, return_tensors='pt').to(device)

    with torch.no_grad():
        outputs = new_model(**input_encoded)

    logits = outputs.logits
    probabilities = torch.nn.functional.softmax(logits, dim=-1)

    pred = torch.argmax(probabilities, dim=-1).item()
    return probabilities, id2label[pred]

We created a function that will take in a string of text and return the probabilities of the predicted sentiments and the predicted sentiment label with the highest probability. Probabilty is the confidence we have in predicted label.
